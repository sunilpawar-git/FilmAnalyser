| 42 | 2026-11-11 | Phase 3 adds one runtime dependency, `pyarrow` (Parquet, DECISIONS #7), pinned in `uv.lock`; licence Apache-2.0 (already on the allowlist), pip-audit clean. | 43 | 2026-11-11 | Storage layout: an output directory holds `manifest.json` and one single-row `chunk_NNNNNN.parquet` per chunk. Parquet files cannot be appended to, so "append-only per chunk" means one new file per chunk. A chunk is written atomically (private temp file in the same directory, fsync, `os.replace`), then its sha256 is recorded in the manifest (also atomic); the manifest is the truth, so an unlisted file is redone and a crash at any instant leaves a consistent store. Every read first checks the file against the manifest hash, then its size, row count, column names/types and feature version, and that it holds the right chunk. Files are written with fixed options (zstd, no dictionary, no pandas metadata, no timestamps) so equal input gives equal bytes (Improvement 5). Non-finite feature values are rejected (a NaN would break byte-equality and downstream maths; Phase 5 must clamp, e.g. silence loudness) | Crash safety, tamper/bit-rot detection and determinism, with no pickle and no pandas anywhere. Size caps (`STORE_MAX_FILE_BYTES`) and `HASH_BLOCK_BYTES` live in `core/config.py` |
| 44 | 2026-11-11 | The feature schema (`storage/schema.py`) lists extractors in order, each with a version and the feature names it returns; columns are `<extractor>.<feature>`, all float64 (plus int32 `chunk_index`). Its `version` is a sha256 of the layout version and that list, written into every Parquet file's metadata. The `Extractor` protocol is unchanged: whoever wires the pipeline declares the feature names (Phase 4). A stored run is keyed by (sha256 of the input film, feature version, `Config.geometry()`: chunk length, overlap, fps, width). Opening a store with a different key raises `StorageError` (`input_/features_/settings_mismatch`): results are never silently mixed, and an existing complete store with the same key is a cache hit (#19). `RAM budget` is deliberately not part of the key | Implements #7 and #19. Changing any setting that changes what a chunk contains must not reuse old results; changing one that does not (RAM budget) should |
| 45 | 2026-11-11 | Resume decodes from the first unfinished chunk: `decode_chunks(path, config, start_chunk=n)` seeks with ffmpeg input seeking (`-ss` before `-i`, so the film before it is never decoded) to the start of chunk n's overlap context, and the chunker reads that context from the stream instead of carrying it. Measured on the synthetic clip (constant frame rate equal to the analysis rate) the resumed chunks are bit-identical to an uninterrupted run's. Not yet shown on real footage: when the source frame rate differs from the analysis rate, a seek can shift the sampling grid by less than one source frame. Tracked as P3-1 in the plan, to be closed by the Phase 4 real-clip smoke test | The exit criterion requires that finished chunks are not re-decoded. Only the overlap (2 s by default) is read again, because extractors need it as context |
